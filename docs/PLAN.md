# BBcall_APRS 计划（BK4802P + STM32F103C8T6 + ST7567，APRS 寻呼机）

> 项目名（暂定）：**BBcall_APRS** —— 用 APRS（AX.25 / 1200 baud Bell202 AFSK）技术路线复刻 BB 机（无线寻呼机）。
>
> 参考项目：MM-Radio (BSD-2)、BG7QKU、BG5ESN FMO、VP-Digi。许可与合规见 [README §10](../README.md#10-许可与合规) 与 [`../licenses/THIRD_PARTY_LICENSES.md`](../licenses/THIRD_PARTY_LICENSES.md)。
>
> 本文件以 **2026-09-16（v0.5）** 的实际实现与实机验证为准；历史 bring-up 过程见 [docs/DEBUG_LOG.md](DEBUG_LOG.md)。

## 1. 当前状态

- MCU：STM32F103C8T6（64KB Flash / 20KB SRAM）；
- 射频：BK4802P，21.25MHz 晶振，仅接收（RX-only），默认 **144.640MHz**；
- 显示：ST7567 12864 **已焊接并点亮**（2026-09-16），三态界面（待机 / 有未读 / 收件箱）在实机可用；
- 音频输入：BK4802 EAROP → 2.2k+22nF RC → 1µF 耦合 → 10k/10k 偏置 → PA1（ADC1_IN1，TIM3 9600Hz）；
- 按键：UP/DOWN/OK = PB12/PB13/PB14（上拉输入、按下为低），驱动与状态机已完成（详见 [DEBUG_LOG §11](DEBUG_LOG.md#11-实机联调lcd-点亮--三态-ui--帧级-rssisnr2026-09-16)）；
- 解码：**已完成**，实机可解真实 APRS 包（含 Mic-E / 普通位置 / 消息）；v0.5 实机连续收包正常；
- 低功耗：**未实现**；当前是 BK4802P 连续 RX + STM32 连续解码。方案只做规划，见本文 [§12](#12-低功耗方案规划暂不执行)。
- 最新固件：**v0.5**（2026-09-16 发布，`text=57324 / data=132 / bss=20220`）；此前 v0.4 于同日发布；
- 实测：SunSDR2 DX 手动 MOX 低功率可稳定解出；但**连续发射仍会漏包**，做不到"发一条看到一条"；
- 漏包率软件优化：已实现逐位相关差积累判决实验，host 回归无回退且有初步改善；**未实机验证**，待按 [§10](#10-下一步方案把漏包率降下来v05-之后) 验收；
- 硬件前端目前是 **天线直接接 BK4802 ANT 脚、无滤波/匹配**，是漏包的主要瓶颈，改进见本文 [§10](#10-下一步方案把漏包率降下来v05-之后) / [§11](#11-硬件改进方案提升解码率)；
- RSSI/SNR 取解码当刻直读的 BK4802 寄存器 24 **原始码值（非标定 dBm）**，单次 I2C 读会随机失败，已用采样兜底。

## 2. 硬件与引脚（以实机为准）

| 功能 | 引脚 | 说明 |
|---|---|---|
| BK4802 SCL | PA9 | GPIO 位敲 I2C |
| BK4802 SDA | PA10 | 写推挽 / 读切输入 |
| BK4802 CE | PA0 | 输出高使能 |
| BK4802 DIO1 | PA8 | 输出低 |
| 对讲机侧 PWR/PTT | PA2 / PA4 | 与 MM-Radio 一致 |
| 音频输入 | **PA1 = ADC1_IN1** | EAROP → 隔直/RC/偏置 → ADC 解调 |
| LCD CS/CLK/MOSI/A0/RST | PB6 / PB3 / PB5 / PB4 / PB7 | 位敲 SPI |
| LCD 背光 | PB0 | 高电平点亮 |
| 蜂鸣 / 振动 | PA6 / PA7 | 输出 |
| LED | PB15 | 状态/告警 |
| 按键 上/下/确定 | PB12 / PB13 / PB14 | 上拉输入 |
| 调试串口 USART3 | PB10=TX / PB11=RX | 115200 8N1 |

> 注意历史文档（2026-09-08 版本）里的「FM 解调输出功放前级」不存在：BK4802P 没有引出功放前模拟音频；AUDC 是麦克风放大器共模节点。实际只用 **EAROP/EARON（D 类功放输出）** 取样，RC 低通 + 隔直 + 偏置后进 PA1。

## 3. 软件架构

```text
BK4802P FM 接收 → EAROP 音频（D 类 PWM）
  → 104 隔直 + RC 低通 + 10k/10k 偏置 → PA1(ADC1_IN1)
  → TIM3 9600Hz 采样（1200 baud × 8）
  → 最近 8 点 1200/2200Hz 定点相关（mark/space）
  → 16 相位并行 + 9 条多周期跳变对齐位时钟
  → NRZI → HDLC（LSB-first、去填充、CRC-16/X.25）
  → AX.25 → APRS（消息 / 位置 / Mic-E）
  → FIFO → 串口 / LCD
```

已实现的关键点：

- 1-bit / 2-bit CRC 纠错（`FIX`/`FIX2`）；
- 参考帧辅助重复包恢复（`REP`）；
- 解码帧 FIFO、重复包抑制（60s）、`RX/U/DUP` 统计；
- 自适应中频增益（`G=4/5/6`）、解码事件时间戳 `[T=...ms]`；
- IWDG 2 秒看门狗、I2C ACK/重试/总线恢复、栈与 RAM 审计修复。

## 5. BB 机功能规划（v0.4 → v1.0）

### 5.1 经典 BB 机核心功能

| 功能 | 说明 | 依赖 |
|---|---|---|
| 按地址接收 | 只显示发给本机的 addressee（呼号/SSID/别名） | 已有解析 |
| 消息提示 | 蜂鸣、振动、LED；响铃/静音/仅振动 | PA6/PA7/PB15 |
| 消息显示 | 呼号、时间、正文；长消息滚动 | ST7567 |
| 收件箱 | 列表、未读/已读、时间排序 | 外部存储 |
| 消息详情 | 翻页、返回、删除、全部删除 | 按键 + UI |
| 未读计数 | 主界面显示未读数 | 存储 |
| 消息时间 | 每条消息接收时间/日期 | RTC |
| 消息去重 | 同一 `msgid`/重复包只存一条 | 已有基础 |
| 存储容量 | 满提示、循环覆盖策略 | 外部 Flash/EEPROM |
| 重复提醒 | 未读消息定时再提醒 | 固件 |
| 按键锁/静音 | 防误操作、夜间静音 | 固件 |
| 背光/对比度 | 背光超时、对比度设置 | ST7567 |
| 状态显示 | 电量、RSSI/SNR/S 表、失联提示 | ADC + RSSI |
| 菜单/设置 | 提示方式、时间、背光、存储管理 | 固件 |

### 5.2 APRS 特有功能

| 功能 | 说明 | 依赖 |
|---|---|---|
| APRS 消息 | `:呼号:正文{msgid`，按呼号过滤 | 已有解析 |
| Ack/Rej | 显示"需要确认"；双向需加发射 | 仅接收时只显示 |
| 群发/公告 | 组地址、APRS Bulletin（`BLN...`） | 固件过滤 |
| 位置包 | `!`/`=`/`/`/`@`、Mic-E | 已有解析 |
| 方位/距离 | 显示经纬度、距离、方位 | LCD + 计算 |
| 天气/遥测/状态 | `_` / `T#` / `>` 包解析 | 扩展解析 |
| 中继路径 | 直发/中继、digipeater 列表 | 已有 |
| 台站列表 | 记录听到的呼号、时间、RSSI/SNR | 存储 |
| Object/Item | 对象/物品名称与位置 | 扩展解析 |
| 过滤 | 指定呼号/关键词/群组，屏蔽广告 | 固件 |
| 优先级 | 紧急/优先消息特殊提示 | 固件 |

### 5.3 状态与系统功能

- 工作状态：接收中、静音、未读、存储满、失联；
- 信号质量：RSSI/SNR/EXN、S 表、AFC；
- 电源：待机降功耗、低电告警、自动关机；低功耗当前未实现，规划见本文 [§12](#12-低功耗方案规划暂不执行)；
- 看门狗/异常复位记录（IWDG 已加）；
- 时间：RTC（DS3231 或内部 RTC）+ 备份电池；
- 配置保存：频率、呼号、提示方式、存储策略。

### 5.4 需要的额外硬件

- 外部存储：W25Q64（消息/台站/字库）或 AT24C512（设置）；
- RTC：DS3231 或 STM32 内部 RTC + 纽扣电池；
- 发射（可选 v1.0）：BK4802 发射通路 + 天线切换；需执照；
- 蓝牙/USB 配置：手机/PC 配置呼号、过滤、导入导出。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| RAM/Flash 紧张 | 外置 W25Q64/AT24C512；字库子集化；`AX25_MAX_FRAME` 已降到 256 |
| 中文显示 | 当前三态 UI 已使用 **Fusion Pixel 12px/10px**（design.md §3.5）；全量中文字集需另行评估字源、布局、Flash 容量和许可 |
| 弱信号解码率 | 射频前端（BPF/匹配/LNA）、音频整形、重复包合并；见本文 [§11](#11-硬件改进方案提升解码率) |
| 低功耗与漏包冲突 | 保持连续 RX 为默认；低功耗改动必须先测基线、分阶段验收，且不得劣化解码率；见本文 [§12](#12-低功耗方案规划暂不执行) |
| VOX/PTT 时序 | 用 150ms VOX 测试音频或手动 MOX；发射端关闭 ALC/压缩 |
| 静噪影响解码 | 解码时保持音频通路常开；软件静噪默认关闭 |
| 双向发射合规 | v1.0 前评估执照与发射滤波/天线切换 |

## 8. PC 端 LCD 模拟器（SDL2）

目标：在 PC 上用 SDL2 模拟 ST7567 128×64 单色点阵，**直接编译固件里的 `lcd_st7567.c` 绘图代码**，无需烧录 STM32 即可看到屏幕效果；并可注入测试 APRS 帧验证 UI。

### 8.1 架构

```text
固件代码（复用）: lcd_st7567.c / fusion_font.h / ax25.c / aprs.c / modem.c
        │ LCD_SIM 分支
        ▼
PC 后端: simulator/src/lcd_sim.c（SDL2 + ST7567 命令状态机）
        │
        ▼
UI harness: firmware-stm32porject/Core/Src/ui_harness.c（三态：待机/有未读/收件箱；模拟器与真机单源共用）
        ▲
        │ ui_feed_ax25()
数据源: simulator/src/sim_feed.c（--wav 解调 / --replay 日志回放 / --demo 示例）
        │
        ▼
主程序: simulator/src/main.c（SDL 事件循环、按键、命令行、自检截图）
```

- `lcd_st7567.c` 加 `#ifdef LCD_SIM`：命令/数据走 `lcd_sim_*`，绘图/fb/字体完全复用；真机仍走 HAL GPIO。
- `sim_hal.c`：最小 HAL/GPIO/延时桩，让 `lcd_st7567.c` 可在 PC 编译。
- `lcd_sim.c`：实现 ST7567 命令子集（页/列地址、显示开关、反显、全亮、起始行、SEG/COM 方向），SDL2 渲染 128×64，支持放大、反显、背光、截图；按 `F3` 可对比两种面板 SEG 方向。
- `ui_harness.c`：收件箱数据模型（消息/位置/Mic-E/其它）+ 待机/列表/详情/删除界面，支持滚动与分页；解析复用 `ax25.c`、`aprs.c`。
- `sim_feed.c`：三种数据源 —— `--wav`（音频→`modem.c`→UI）、`--replay`（串口日志 `[RAW] hex=`）、`--demo`（内置示例）。
- 构建：`simulator/build_win.ps1`（Windows 免安装，TinyCC + 内置 SDL2，推荐）；`simulator/CMakeLists.txt` 与 `simulator/Makefile` 保留给装好 MSYS2 / vcpkg / w64devkit 的机器。

## 10. 下一步方案：把漏包率降下来（v0.5 之后）

> **更新（2026-09-17）**：漏包率是端到端指标。一次漏包可能来自射频前端、音频链路、解调判决、CRC 失败、modem 队列溢出、纠错阻塞主循环或 UI 消费过慢。
> 软件专项优化必须先能区分这些原因；硬件改动和软件改动分开验证，避免无法归因。低功耗仍单独放在 [§12](#12-低功耗方案规划暂不执行)，不与漏包率优化混测。

背景：v0.5 实机解码正常，但**连续发射仍会漏包**。当前硬件无滤波/匹配，射频前端仍可能是最大瓶颈；但软件侧也不能只看"解出几帧"，还需要观测队列、重复帧、纠错耗时和 ISR 负载。

### 10.1 P0：建立漏包率基线

**目的**：先得到可复现的基线，再判断任何软件或硬件改动是否有效。

- 固定发射设备、天线、距离/衰减、频率、FM 频偏、音频电平和测试环境；
- 先做 20 包冒烟测试，确认测试流程；正式对比至少 **50 包**，最好 **100 包**；
- 记录发送帧数、CRC 正确帧数、去重后唯一帧数、DUP/FIX/FIX2/REP、RSSI/SNR、无信号底噪；
- 每次测试保存时间、温度、供电方式、发射功率、天线和衰减器配置；
- 输出基线格式：`sent=N, unique=x, crc=y, dup=z, fixed=f, miss=m`。

### 10.2 P1：补齐软件链路观测

**目的**：把"没解出来"和"解出来但软件丢掉"分开。

- **modem 好帧队列**：增加入队成功数、满队列丢弃数、队列峰值占用；
- **bad/plausible 队列**：增加入队成功数、满队列丢弃数、纠错成功/失败数；
- **重复帧观测**：统计 modem 层重复 CRC 帧，区分"多相位重复解出"与"空中重复发送"；
- **纠错耗时**：测量单帧 1-bit / 2-bit 纠错耗时，观察是否存在主循环阻塞；
- **ISR 负载**：用 DWT 或等效方式测量 `modem_adc_sample()` 平均/最大周期；
- **消费路径**：记录主循环取出帧到 UI 完成处理的时间，确认是否被 LCD/I2C/提示音阻塞；
- **观测入口**：优先串口；无串口时用 ST-Link Live Expressions；诊断 UI 只作为辅助，不先做复杂菜单。

### 10.3 P2：保留并验证低风险软判决

当前已实现第一版**逐位相关差积累判决**：16 相位与跳变对齐路径不再用单点相关差硬判决，而是把一个位窗口内的 `m1-m2` 或半采样插值积累后再判 mark/space。它不是完整的多相位似然合并，是风险更低的第一步。

- **已完成**：host 回归工具 `tools/regression_modem.c` 用干净 WAV 对比，原 16 相位路径无回退；
- **初步收益**：加噪用例中有改善，例如 `0.02 amplitude / 0.010 noise` 场景从 4 帧提升到 9 帧；
- **已知限制**：干净 WAV 可能多输出重复帧；极弱信号 `0.01 amplitude` 仍全部失败，说明射频/音频前端仍是主要瓶颈；
- **风险**：`TIM3` ISR 为 9600Hz，新增 16+9 路累加，必须实机确认 CPU 余量；
- **验收**：固件可编译、ISR 最大耗时在预算内、P0 基线对比不劣化、50–100 包实测有可复现收益；
- **回退策略**：若 ISR 负载或实测不稳定，增加编译开关关闭该实验路径，恢复单点硬判决。
  - 已实现：`modem.c` 的 `BBCALL_MODEM_SOFT_DECISION`（1=软判决，默认；0=单点硬判决），
    也可用 `-DBBCALL_MODEM_SOFT_DECISION=0` 覆盖。关掉后 `bss` 20132 -> 19964（省 168 字节），
    两个预编译产物：`Debug/BBCall_APRS.hex`（软判决）、`Debug/BBCall_APRS_harddec.hex`（回退版）。

> **2026-09-17 host A/B 复测（重要修正）**：用 10 个**不同**包拼成一段音频（每包间隔 250ms），
> 再做多档衰减 + 高斯加噪，用 `tools/regression_modem.c` 分别跑软判决与单点硬判决，按**整帧字节去重**统计唯一包数：
>
> | 素材（amp/noise） | 软判决 unique | 硬判决 unique | 软判决总帧 | 硬判决总帧 |
> |---|---|---|---|---|
> | 1.00 / 0.000 | 10 | 10 | 163 | 160 |
> | 0.30 / 0.010 | 10 | 10 | 159 | 147 |
> | 0.15 / 0.010 | 10 | 10 | 149 | 139 |
> | 0.10 / 0.010 | 10 | 10 | 133 | 130 |
> | 0.06 / 0.008 | 10 | 10 | 125 | 127 |
> | 0.04 / 0.006 | 10 | 10 | 122 | 123 |
> | 0.02 / 0.005 | 10 | 10 | 110 | 69 |
> | 0.015 / 0.004 | 10 | 10 | 77 | 25 |
> | 0.010 / 0.003 | 0 | 0 | 0 | 0 |
>
> **结论**：在这类合成素材上，软判决与单点硬判决解出的**唯一包数完全相同**（可用区间内都是 10/10，
> 再弱一档两版同时归零），软判决只是**重复帧更多**（弱档 77 vs 25）。因此本节前面写的"4 帧提升到 9 帧"
> 属于**总帧数**口径、含重复解出，不能当作"多收到几个包"。
> 真实收益必须在实机上按 P0 口径（唯一包数）验证；合成素材缺少频偏、衰落、多径，无法替代空中测试。
> 若实机唯一包数无提升，按回退策略关掉该实验路径即可（RAM 还省 168 字节）。

### 10.4 P3：队列、重复帧与纠错调度

只有 P1 数据证明软件侧确实丢帧后，才做本阶段。

- **队列溢出**：若好帧队列频繁满，优先做去重/消费优化，不盲目扩大队列；`STM32F103C8T6` 只有 20KB RAM，扩队列要先核对 `bss` 和栈余量；
- **重复帧**：评估 modem 入队前轻量去重的 CPU 成本，避免重复 CRC 帧占用队列；
- **纠错阻塞**：若 2-bit 纠错阻塞主循环，考虑限制纠错长度、时间片化或只在低风险场景启用；
- **bad 队列污染**：如果大量噪声候选帧进入 bad 队列，收紧 `ax25_plausible()`，而不是直接增强纠错；
- **验收**：队列溢出为零或可解释，主循环阻塞时间低于连续收包安全阈值，实测漏包率不劣化。

### 10.5 P4：扩充离线回归数据集

不要只用现有少量 WAV 调参，避免过拟合。

- 覆盖不同帧长：短消息、普通位置、长注释/多路径帧；
- 覆盖不同幅度：强、中、弱、临界；
- 覆盖不同噪声、频偏、DC 偏置和采样起始相位；
- 保留真实空中录音和真实日志回放；
- 使用 `tools/regression_modem.c` 做 modem 层统计，`bbcall_sim --replay` 做应用/UI 层回归；
- 注意：`bbcall_sim --wav` 可能因 bad frame 纠错耗时较长，不适合作为唯一 modem 回归入口。

### 10.6 P5：硬件前端改进

射频前端改进放在软件观测与软判决验证之后单独进行；详细器件和电路方向见 [§11](#11-硬件改进方案提升解码率)。

- 优先补 144–146MHz 带通、匹配、ESD 与隔直；
- 可选 LNA 放在 BPF 后；
- 每次只改硬件一处，按 P0 同一口径对比。

### 10.7 P6：自适应判决门限

自适应门限后置，只有在 P0–P5 显示残余漏包与频偏、增益漂移或判决偏置相关时再做。

- 先用离线数据统计 mark/space 相关差分布；
- 设定上下限和慢速自适应，避免噪声被放大成有效音调；
- 必须同时观察 bad 帧数量与纠错耗时，防止"多解出垃圾帧"导致更多丢包。

### 10.8 漏包率优化验收

| 项 | 要求 |
|---|---|
| 基线 | 同一条件下至少 50 包，推荐 100 包，结果可复现 |
| 软件改动 | 离线回归无回退，固件编译通过，ISR 负载实测 |
| 队列 | 好帧/bad 队列丢弃可观测；无未解释丢帧 |
| 纠错 | FIX/FIX2 收益和耗时都被记录 |
| 实机 | 同条件下与基线对比，unique 帧数提升且不增加误帧 |
| 稳定性 | 连续收包至少 30 分钟无 IWDG 复位、I2C 卡死或 UI 卡死 |
| 归因 | 射频、软件、低功耗改动分开提交和测试 |

## 11. 硬件改进方案（提升解码率）

当前硬件：天线直接短接到 BK4802 的 ANT 脚，**没有隔直、滤波和 50Ω 匹配**。这会导致灵敏度下降、FM 广播/409MHz 玩具机等强带外信号阻塞前端、底噪升高（EXN 偏大），是当前弱信号解码率的主要瓶颈。按收益排序如下。

### 11.1 射频前端（收益最大）

目标结构：

```text
天线(50Ω) → ESD保护 → 100pF隔直 → 144–146MHz带通 → [可选LNA] → π/L匹配 → 100pF隔直 → BK4802 ANT
```

- **隔直/保护**：ANT 脚串 100pF C0G（数据手册典型 C1=100pF）；天线端加 ESD 二极管/阵列（BAT54S/BAV99 等）；RF 走线按 50Ω 设计，短而直，两侧打地过孔。
- **2m 带通**：优先从坏掉的 2m 手台/接收机拆前端带通或螺旋滤波器，或购买 144–146MHz 带通模块；要求插损 ≤2–3dB，对 88–108MHz、409MHz 抑制 ≥30dB。自建 LC 带通：中心 144.64MHz、带宽 3–5MHz、3 阶；并联谐振起始值约 L=82–100nH、C=12–15pF，耦合 2–5pF，用 NanoVNA 调到 S11<-10dB、插损<2dB。
- **与 BK4802 匹配**：BPF 与 ANT 脚之间加 π 型或 L 型匹配（串 L + 两端并 C）；无 VNA 时用弱信号源调 L/C，使 RSSI/SNR 最大、EXN 最小，目标弱信号 RSSI 提升 6dB 以上。
- **可选 LNA**：BPF 之后加 PGA-103+ / SPF5189Z（NF≈0.5dB）；强信号环境在 LNA 前加 3–6dB 衰减器或 BAP64-02 PIN 限幅器，避免 LNA 饱和。

### 11.2 音频链路（EAROP → PA1）

- 单级 RC 升级为两级 RC 或 LC 低通，彻底滤掉 D 类 ~100kHz 载波，同时保留 1200/2200Hz；
- 加比较器整形（LM393/TLV3501，阈值 1.65V + 迟滞）或轨到轨运放带通（MCP6002/TL072，中心约 1.7kHz、增益 5–10 倍）；
- 音频线用屏蔽线/双绞线，尽量短、远离 RF 和数字线；PA1 对地并 100pF 抑制 RF；
- 耦合 1µF、偏置 100k/100k，静态 1.65V，摆幅 0.7–1.5Vpp，避免削顶。

### 11.3 电源、接地与屏蔽

- MCU 与 BK4802 用低噪声 LDO（TPS7A4700/LT3045，或 AMS1117 + 100µF+10µF+100nF），优先电池/线性电源，少用 USB 供电；
- BK4802 的 VCCRF/VCCIF/VCCAUD/VDDVCO 分别去耦，VSSAUD 单独星型接地；
- 电源线串磁珠/共模扼流圈；数字地与射频地在电源入口单点相连；
- 射频部分加金属屏蔽罩，天线座就近接地，MCU/晶振/串口线远离 RF 前端。

### 11.4 晶振与频率精度

- 21.25MHz 晶振换 ±10ppm 以内 TCXO/高精度晶振，负载电容按手册；走线短、包地；
- 保持 AFC 开启（当前 reg20 默认开），弱信号下频偏会吃掉解码余量。

### 11.5 强信号与衰减

- 近场/强台：加 3/6/10dB 衰减器或步进衰减器，避免 BK4802 前端/中频饱和；
- 弱台：BPF + LNA；LNA 必须在 BPF 之后，并加限幅保护。

### 11.6 发射端（SunSDR2 DX）

- 音频线或手动 MOX，避免 VOX 时序丢前导；FM 频偏约 3kHz，关闭 ALC/压缩/EQ，音频峰值约 -6dB；
- 发射天线/馈线调好 SWR；近场测试用假负载+衰减器，别让接收端过载。

### 11.7 验证与测量

- NanoVNA：调天线/BPF/匹配（S11<-10dB，插损<2dB）；
- SDR/频谱仪：看 2m 附近是否有强带外信号（FM 广播、寻呼、409MHz 玩具机）；
- 步进衰减器：测灵敏度与解码率，记录 `RSSI/EXN/RX/U/DUP/G/OT` 对比改动前后。

## 12. 低功耗方案（规划，暂不执行）

> **状态（2026-09-17）**：规划稿，**未实现、未合入、未执行**。
> v0.5 为了保证任意时刻 APRS 帧都能被收到，采用 **BK4802P 连续 RX + STM32 连续采样解码**；
> 这不是传统寻呼机的低占空比监听。本节先完善方案，不改固件、不改硬件、不切换默认模式。
> 应在漏包率量化与射频前端改进之后单独开分支验证。

### 12.1 当前实现边界

- 当前射频链路：BK4802P 保持连续 RX，没有 RF duty cycle；
- 当前 MCU 链路：TIM3 约 9600Hz 触发采样，`TIM3_IRQHandler` 内启动 ADC 并等待 EOC 后送入 `modem_adc_sample()`；这是功耗优化的核心改造点；
- 当前外设：LCD、背光、按键扫描、RSSI/SNR 与软件静噪查询、调试串口输出、IWDG 均按现有 v0.5 逻辑运行；
- 当前没有任何可靠的整机电流、MCU 空闲率、BK4802P 连续 RX 电流、背光电流和真实续航数据。

### 12.2 目标与非目标

**目标**

1. 在不牺牲 APRS 接收能力的前提下，逐步降低平均功耗；
2. 把功耗改造成可配置、可测量、可回退的实验分支，而不是一次性替换 v0.5 行为；
3. 给出真实电池容量、实测电流和续航估算方法，避免只报省电百分比。

**非目标**

1. 不把“省电”优先级置于“收到帧”之前；
2. 不在默认固件中关闭 BK4802P 或采用周期性 RF 唤醒；
3. 不在缺少电流基线前进入 STOP/STANDBY；
4. 不使用估算电流代替实测电流，也不承诺未验证的续航。

### 12.3 设计原则

1. **先收得到，再省电**：任何低功耗改动的第一验收项都是解码成功率/漏包率不得劣化；
2. **默认保持连续 RX**：APRS/AX.25 帧可能在任意时间开始，关闭射频后无法保证收到随机帧；
3. **先测量，后优化**：没有整机电流与解码成功率基线前，不直接进入 STOP/关闭射频等高风险改动；
4. **可回退**：低功耗模式用编译期开关和运行时配置控制，默认关闭；
5. **不误导 UI**：进入低功耗后，按键和收包必须能唤醒屏幕；电量/信号页不能显示未测量的假数据；
6. **一次只改一层**：不能同时改射频、DMA、STOP、显示和电池，否则无法归因。

### 12.4 低功耗层级与优先级

| 层级 | 内容 | 风险 | 优先级 |
|---|---|---|---|
| L0 基线测量 | 整机/模块电流、解码率、漏包率 | 低 | 第一步 |
| L1 外设省电 | 背光超时、LCD Display Off、按键/收包唤醒、提示音与振动限时 | 低 | 第二步 |
| L2 MCU 计算省电 | ADC DMA 双缓冲、解码器批量处理样本、空闲 WFI/Sleep | 中 | 第三步 |
| L3 外设任务调度 | 降低非关键周期任务频率；S-meter、I2C、串口诊断按需执行 | 中 | 与 L2 一起评估 |
| L4 MCU STOP | STOP/STANDBY + RTC/EXTI 唤醒 | 高 | 暂不执行 |
| L5 RF duty cycle | BK4802P 间歇 RX、前导/时隙唤醒 | 很高 | 仅调研，默认禁止 |

### 12.5 L1：显示与提示功耗

- 背光继续使用 PB0 超时关闭；可把 15s 超时做成配置项；
- LCD 空闲 30–60s 后进入 Display Off；收到新帧或任意按键后恢复并整帧重绘；
- Display Off 后不假设显存内容完整；唤醒后必须按当前三态 UI 状态重绘；
- 蜂鸣/振动必须设置最大持续时间、重复间隔和静音模式；长时间未读不做高频重复提醒；
- 未读提示策略：首次强提醒，之后低频提醒；不能为了提示而持续开启大电流外设；
- UI 唤醒必须同时覆盖按键、新帧、串口命令三类入口，避免“收到了但屏幕不可见”。

### 12.6 L2：MCU 采样与解码功耗

- 先测当前 CPU 占用与空闲时间；若空闲时间可观，再把 ADC 采样改为 **TIM3 触发 ADC + DMA 双缓冲**；
- 必须先确认 STM32F103 上 TIM3 触发 ADC 的触发源、采样时间、DMA 半满/全满中断和 9600Hz 实际节拍；
- `modem.c` 从“每次中断处理 1 个样本”改为“每半缓冲/全缓冲批量处理 N 个样本”；采样率仍保持 9600Hz；
- 批处理期间保持现有定点相关、NRZI、HDLC、CRC 纠错行为不变；
- CPU 完成一批样本后进入 `WFI` 或 Sleep，由 DMA 半满/全满中断唤醒；
- IWDG 仍需独立喂狗；不能因为 WFI 或批量处理导致看门狗复位；
- 调试串口周期输出做成可关闭；无串口时不要让格式化打印阻碍低功耗；
- 是否降低主频、是否切换 HSI/PLL，必须在解码余量、USART3、I2C 位敲时序全部实测后再决定；第一版不建议同时做。

### 12.7 L3：外设任务调度

- S-meter/I2C 周期读可改为可配置；无 UI 需求或低功耗模式下降低频率，解码当刻 RSSI/SNR 读数保留；
- 软件静噪查询不能为了省电而抢占正在解码的包；帧进行中应优先完成解码；
- LCD 局部刷新优先于全屏刷新；但三态切换和唤醒后仍按 `design.md` 规范整帧重绘；
- 电池电压采样间隔可取 30–60s；阈值必须用真实电池实测，不使用猜出来的边界；
- 若使用 LDO，必须测量静态电流；LDO 静态电流可能比 MCU Sleep 省下的电流更重要。

### 12.8 L4：MCU STOP 边界

- STOP 模式只作为后续实验，不作为默认方案；
- F103 STOP 唤醒后时钟通常回到 HSI，需要重新配置 PLL、总线时钟和依赖时钟的外设；
- LCD SPI/I2C、BK4802P I2C、SysTick、调试串口、按键去抖都需要重新评估；
- IWDG 不会因为 STOP 停止；STOP 唤醒周期必须明显小于 IWDG 超时，否则要先调整看门狗策略；
- 若 BK4802P 仍保持连续 RX，MCU STOP 带来的整机收益可能有限，必须先测量射频电流占比；
- 唤醒源至少要覆盖按键 EXTI、新帧事件或协议化唤醒信号；未确认 BK4802P 事件输出能力前不实施。

### 12.9 L5：射频占空比边界

- **不满足通用 APRS 接收**：帧开始时间未知；BK4802P 关闭期间到达的 AFSK 数据会直接丢失；
- 周期性短暂开 RX 只能作为“能量探测”，不能保证捕获随机 APRS 帧；
- 只有满足下列条件之一才考虑 RF duty cycle：
  - 发射端约定长前导，且前导长度大于 RF 唤醒时间 + 同步余量；
  - 采用固定时隙/唤醒窗口，收发双方协议同步；
  - 明确接受漏包率上升，仅用于省电演示模式。
- 需要先确认 BK4802P standby/sleep 状态、恢复时间、寄存器是否保持、I2C 状态和音频链路恢复顺序；
- RF duty cycle 不能与当前“漏包率优化”目标同时推进，否则无法归因。

### 12.10 电池与功率预算

> 下表只作为工程预算参考，不代表本项目实测续航，也不作为宣传数据。

| 电池参考 | 常见容量区间 | 备注 |
|---|---:|---|
| AAA 碱性/镍氢 | 约 800–1200mAh | 传统小型 BB 机常用；脉冲电流和截止电压会导致有效容量下降 |
| AA 碱性/镍氢 | 约 1800–2800mAh | 体积更大，续航余量更好 |
| 1S LiPo/Li-ion | 约 500–2000mAh | 需要保护、充电管理和低电压截止 |

功率预算方法：

1. 以实测 `I_avg` 为基础，不使用器件手册之外的估算值作为结论；
2. 可用电流上限按 `0.8 × 电池容量 / 目标续航` 预算，保留低温、老化和脉冲损耗；
3. 例：1000mAh 电池按 24h 续航，平均电流约需低于 33mA；72h 约 11mA；7 天约 4.8mA；
4. 若 BK4802P 连续 RX 电流已超过预算，MCU/LCD 省电无法解决根本问题；
5. “待机功耗”定义为无背光、无提示、无新包但保持连续 RX；“工作功耗”定义为有包解码、UI 刷新、提示音/振动/背光工作时的功耗；
6. 最终必须给出实测电路、电池型号、温度、峰值电流和平均电流。

### 12.11 电源与测量方案

- 使用电池或外部可调电源供电，串入电流表/uCurrent/采样电阻测量整机平均电流；
- 有条件时分支测量：MCU、BK4802P、LCD、背光、蜂鸣/振动，避免把 LDO 静态电流和射频电流混在一起；
- 至少记录以下工况：
  1. 当前 v0.5 固件，连续 RX + LCD 显示；
  2. 背光开/关；
  3. LCD Display On/Off；
  4. 有信号连续收包；
  5. 无信号静默接收；
  6. 蜂鸣、振动单次触发；
- 每个工况记录：平均电流、峰值电流、`RX/U/DUP/FIX/FIX2/REP`、漏包数；
- 电流数据必须和解码回归数据同一次测试生成，不能只报省电百分比。

### 12.12 验收门槛

| 项 | 要求 |
|---|---|
| 解码率 | 与关闭低功耗的基线相比，同条件下不下降；至少完成离线 WAV/日志回归 + 实机同一发射条件 50 包对比 |
| 随机帧 | 默认模式下不得依赖长前导、时隙或发射端改造 |
| 唤醒 | 按键唤醒和收包唤醒必须可靠；LCD 唤醒后 200ms 内完成可读重绘 |
| 稳定性 | 连续运行至少 8h，无 IWDG 复位、I2C 卡死、LCD 花屏 |
| 回退 | 低功耗模式可一键关闭；关闭后行为与 v0.5 基线一致 |
| 电流报告 | 给出平均电流、峰值电流、测试电路和工况，不使用估算值充当实测值 |

### 12.13 建议实施顺序

1. **P0 测量基线**：只测电流和解码率，不改功能；
2. **P1 L1 外设省电**：背光/LCD/提示策略，风险最低；
3. **P2 L2/L3 计算与任务省电**：ADC DMA + 批处理 + WFI；
4. **P3 L4 STOP**：仅在外设调度完成且仍有必要后评估；
5. **P4 L5 RF duty cycle**：只作为协议化省电方案，不进入默认固件。
